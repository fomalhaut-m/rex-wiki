# MySQL 索引设计的原则

1. 索引不是越多越好，一个表最好不要超过 5 个索引。
2. 只给高频查询增加索引；低频查询可借助全表扫描或应用层缓存兜底，避免无效索引拖累写入。
3. 优先给高基数字段创建索引。
   - 高基数字段：字段值数量多，重复值少的字段。
   - 计算公式：字段值数量 / 表记录数
   - 建议值：≥ 0.1
   - 例如：性别字段只有 2 个值，记录数为 10000 时，比值 = 2/10000 = 0.002。
4. 索引字段的空间占用越小越好；字段类型越小，单页可容纳的索引条目越多，IO 次数越少，查询效率越高。
5. 不要给有 NULL 值的字段建索引；NULL 无法参与多数索引运算（如 `=`、`<`、`>`），建议建表时设置 `NOT NULL DEFAULT` 默认值。
6. 频繁更新的字段不要创建索引。
   - 每次更新都会同步维护索引结构，更新成本随索引数量线性增长。
   - 例如：年龄。
   - 替代方案：存储出生年月日，按需计算年龄。
7. 业务允许的情况下，尽可能使用组合索引；多条件查询合并为复合索引，比多个单列索引更高效。
8. 创建索引要遵循最左原则；复合索引 `(a, b, c)` 可命中 `a` 或 `a+b` 或 `a+b+c` 的查询，跳过 `a` 直接使用 `b`、`c` 无法命中。
9. 主键建议使用自增索引。
   - AUTO_INCREMENT：写入连续，避免页分裂。
   - 雪花算法（Snowflake）：分布式场景全局唯一且基本有序，同样可避免页分裂。
   - 避免使用 UUID 等无序主键：插入随机位置会频繁触发页分裂，索引性能急剧下降。

> 在迁移数据的情况下，先创建表，然后迁移数据，最后创建索引；导入完成后再建索引只需扫描一次数据，效率显著提升。
